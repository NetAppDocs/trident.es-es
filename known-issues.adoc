= Problemas conocidos
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Los problemas conocidos identifican problemas por los que el uso correcto de esta versión del producto puede resultar imposible.

Los siguientes problemas conocidos afectan a la versión actual:



[[trident-node-pods-might-detach-in-use-volumes-during-upgrade-to-26-10-0]]
== Los pods de nodo de Trident podrían desconectar los volúmenes en uso durante la actualización a la versión 26.10.0

No actualices a Trident 26.10.0 desde Trident 25.10 ni desde ninguna versión anterior. Durante el arranque, es posible que los pods de nodo de Trident desconecten volúmenes que aún estén en uso. Los pods afectados podrían fallar con el error `volume ... is not staged`. Se está desarrollando una corrección. Espera a que se publique una versión que incluya la corrección antes de actualizar.



[[volumes-remain-attached-after-upgrading-from-trident-22-10-or-earlier]]
== Los volúmenes siguen adjuntos tras actualizar desde Trident 22.10 o una versión anterior

Este problema afecta a los clientes que actualizan directamente de Trident 22.10 o versiones anteriores a Trident 26.10 mientras hay volúmenes conectados. Las actualizaciones desde Trident 23.01 o posterior no presentan este problema.

Tras la actualización, es posible que los volúmenes afectados no se desconecten. Los Pods que usan volúmenes ReadWriteOnce (RWO) no pueden moverse a otro nodo y pueden mostrar un error de conexión múltiple. Eliminar el PersistentVolume (PV) también podría bloquearse.

Para solucionar este problema, en el nodo que tiene la asociación de volumen obsoleta, elimina el archivo  `volumePublishInfo.json` restante del directorio  `globalmount` de ese volumen.



[[volumesnapshots-not-reaching-readytouse-state]]
== VolumeSnapshots no alcanza el estado ReadyToUse

[WARNING]
====
Existe un problema conocido con el `csi-snapshotter` sidecar. En todas las versiones de Kubernetes, VolumeGroupSnapshots `v1beta1` impide que VolumeSnapshots llegue al estado `ReadyToUse`.

====
Hay dos soluciones alternativas:

. Elimina los CRD de VolumeGroupSnapshots para desactivar VolumeGroupSnapshots y luego vuelve a instalar Trident.
. Instala VolumeGroupSnapshots `v1beta2` y `snapshot-controller` versión 8.4.0 o posterior, y luego vuelve a instalar Trident. VolumeGroupSnapshots no funcionan en versiones de Kubernetes anteriores a v1.34.




[[restoring-restic-backups-of-large-files-can-fail]]
== La restauración de copias de seguridad de archivos grandes de Restic puede fallar

Al restaurar archivos de 30 GB o más grandes desde una copia de seguridad de Amazon S3 realizada con Restic, la operación de restauración puede fallar. Como solución alternativa, realice una copia de seguridad de los datos utilizando Kopia como gestor de copias de seguridad (Kopia es el gestor de copias de seguridad predeterminado). Referirse a https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-protect-apps.html["Proteja las aplicaciones con Trident Protect"^] para obtener instrucciones.
